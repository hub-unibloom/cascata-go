Sim, são essas duas. E o problema **não é a chamada** — é um bug no parser do Cascata.

---

### O que tá acontecendo

O parser do select tá fazendo split ingênuo por vírgula:

```
id, price, custom_description, product_catalog(name,brand)
```

Ele divide tudo por `,` e aí vira:

```
"id"
"price"  
"custom_description"
"product_catalog(name"   ← quebrou aqui
"brand)"                 ← e jogou isso como coluna separada
```

Daí o erro: `invalid column name 'product_catalog(name'`. Ele nunca chegou a entender que era um embedding.

---

### A causa raiz

O parser precisa **respeitar parênteses** antes de splitar por vírgula. A lógica correta é:

> só divide na vírgula se o `depth de parênteses == 0`

Algo assim:

```go
func splitSelectFields(s string) []string {
    var fields []string
    depth := 0
    start := 0
    for i, ch := range s {
        switch ch {
        case '(':
            depth++
        case ')':
            depth--
        case ',':
            if depth == 0 {
                fields = append(fields, strings.TrimSpace(s[start:i]))
                start = i + 1
            }
        }
    }
    fields = append(fields, strings.TrimSpace(s[start:]))
    return fields
}
```

---

### Resumo

| | |
|---|---|
| **Chamada errada?** | Não, sintaxe correta |
| **Bug no Cascata?** | Sim, no parser de `select=` |
| **Onde corrigir** | Função que faz split dos campos antes de resolver embeddings |

Depois do split correto aí você ainda precisa implementar a resolução do embedding em si (detectar `resource(cols)`, resolver a FK `product_catalog_id → product_catalog`, fazer o JOIN). Mas o primeiro crash é esse parser.
