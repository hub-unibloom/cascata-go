# CASCATA GO - FLUXO DE VERSIONAMENTO E INSTALAÇÃO
# =================================================
# Documento para garantir funcionamento correto em ambas as VPS
# Máquina 1: Modo Standard (chave no .env)
# Máquina 2: Modo Sovereign Elite (chave em RAM)

## RESUMO DAS CORREÇÕES IMPLEMENTADAS

### BUG 1 - Validação Fraca gen_hex_secret() [CORRIGIDO]
- Problema: Validava apenas 16 chars mínimo, mas crypto-engine exige 64
- Solução: Alterado `if [ ${#RESULT} -lt 16 ]` para `if [ ${#RESULT} -lt 64 ]`
- Arquivo: install.sh.txt:662-665

### BUG 2 - State File Pula Phase 2 [CORRIGIDO]
- Problema: PHASE2_DONE=true fazia skip da geração de secrets
- Consequência: Após `docker compose down && up`, MASTER_SECRET não estava no .env
- Solução: Adicionada verificação `|| [ -z "${MASTER_SECRET:-}" ] || [ ${#MASTER_SECRET} -lt 64 ]`
- Arquivo: install.sh.txt:1984-1992

### BUG 3 - Unseal Sem Header de Auth [CORRIGIDO]
- Problema: Curl de unseal automático não enviava header X-Crypto-Auth
- Consequência: Sempre falhava com 401 Unauthorized
- Solução: Adicionado `-H "X-Crypto-Auth: ${INTERNAL_CTRL_SECRET}"`
- Arquivo: install.sh.txt:2010-2013

### BUG 4 - Recuperação Pós-Reboot [CORRIGIDO]
- Problema: Variáveis perdidas após reboot (shell novo)
- Solução: Adicionada seção de recuperação do .env antes de gerar secrets
- Arquivo: install.sh.txt:802-820

### BUG 5 - keystore.Unlock() Reverte KEK [CORRIGIDO]
- Problema: Revertia KEK em qualquer erro, inclusive arquivo inexistente
- Solução: Distinguir entre IsNotExist vs decryption failed
- Arquivo: store.go:94-114

### BUG 6 - Validação de MASTER_SECRET Lida [CORRIGIDO]
- Problema: Aceitava chave inválida do .env sem validar tamanho
- Solução: Validar `${#MASTER_SECRET} -ge 64` ao ler do .env
- Arquivo: install.sh.txt:827-839

## FLUXO ESPERADO - MÁQUINA 1 (MODO STANDARD)

### Instalação Inicial
1. Usuário executa `./install.sh`
2. Escolhe opção 1 (Standard)
3. Script gera MASTER_SECRET de 64 chars
4. Script injeta CASCATA_MASTER_SECRET no .env
5. Script inicia containers
6. Crypto-engine lê chave do .env via docker-compose
7. Crypto-engine deriva KEK e descriptografa/cria keystore
8. Sistema funciona normalmente

### Após Reboot ou `docker compose down && up`
1. Containers param
2. Usuário executa `docker compose up -d`
3. Crypto-engine reinicia
4. Docker Compose passa CASCATA_MASTER_SECRET do .env
5. Chave ainda é válida (64 chars)
6. Crypto-engine deriva KEK e descriptografa keystore existente
7. Sistema funciona sem intervenção manual

---

## FLUXO ESPERADO - MÁQUINA 2 (MODO SOVEREIGN ELITE)

### Instalação Inicial
1. Usuário executa `./install.sh`
2. Escolhe opção 2 (Elite)
3. Script gera MASTER_SECRET de 64 chars
4. Script NÃO salva CASCATA_MASTER_SECRET no .env (remove se existir)
5. Script mostra chave na tela para usuário anotar
6. Script inicia containers
7. Crypto-engine inicia sem chave (SEALED mode)
8. Script faz unseal automático com MASTER_SECRET em memória
9. Sistema funciona

### Após Reboot ou `docker compose down && up`
1. Containers param
2. Crypto-engine reinicia sem chave (SEALED mode)
3. Usuário precisa inserir chave manualmente:
   - Via painel web: System Settings > Unseal Engine
   - Ou via API direta: `curl -X POST -H "X-Crypto-Auth: <secret>" -d '{"master_secret": "<chave>"}' http://localhost/api/control/auth/sovereign/unseal`
4. Crypto-engine valida chave e descriptografa keystore
5. Sistema funciona normalmente

### VPS 1 - Modo Standard (Teste Completo)
```bash
cd ~/cascata

# 1. Instalação inicial
./install.sh
# Escolher opção 1 (Standard)

# 2. Verificar se está funcionando
docker logs cascata-crypto-engine | grep "KeyStore loaded"

# 3. Simular reboot
docker compose down

# 4. Subir novamente
docker compose up -d

# 5. Verificar se ainda funciona
docker logs cascata-crypto-engine | grep "KeyStore loaded"

```

### VPS 2 - Modo Elite (Teste Completo)
```bash
cd ~/cascata

# 1. Instalação inicial
./install.sh
# Escolher opção 2 (Elite)
# ANOTAR A MASTER_SECRET MOSTRADA!

# 2. Verificar se está funcionando
docker logs cascata-crypto-engine | grep "unsealed"

# 3. Simular reboot
docker compose down

# 4. Subir novamente
docker compose up -d

# 5. Verificar que está SEALED
docker logs cascata-crypto-engine | grep "SEALED"
# Esperado: "KeyStore is SEALED. Awaiting manual unseal."

# 6. Fazer unseal manual (substituir <MASTER_SECRET> pela chave anotada)
curl -X POST http://localhost/api/control/auth/sovereign/unseal \
  -H "Content-Type: application/json" \
  -H "X-Crypto-Auth: $(grep INTERNAL_CTRL_SECRET .env | cut -d= -f2)" \
  -d '{"master_secret": "<MASTER_SECRET>"}'

# 7. Verificar que desbloqueou
docker logs cascata-crypto-engine | grep "unsealed"
# Esperado: "KeyStore loaded and READY"
```

## CÓDIGOS DE ERRO E SOLUÇÕES

### "MASTER_SECRET must be at least 64 hex characters"
- **Causa**: Chave gerada com menos de 64 chars
- **Solução**: Correção aplicada em gen_hex_secret()

### "KEK derivation failed — entering SEALED mode"
- **Causa**: Chave inválida ou vazia
- **Comportamento**: Container fica saudável em modo SEALED (esperado para Elite)

### "Unauthorized" no unseal
- **Causa**: Header X-Crypto-Auth ausente
- **Solução**: Correção aplicada no curl de unseal automático

### "PHASE2_DONE=true mas MASTER_SECRET não está definida"
- **Causa**: State file corrompido ou script interrompido
- **Solução**: Script agora re-executa phase 2 se MASTER_SECRET ausente
