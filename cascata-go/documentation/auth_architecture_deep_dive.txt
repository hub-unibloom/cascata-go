## 1.1 O Que É o Cascata Auth?

O sistema de autenticação do Cascata é um ORQUESTRADOR DE IDENTIDADE 
SOBERANO (Sovereign Identity Orchestrator) enterprise-grade que vai muito 
além de "login com email/senha".

### Capacidades Core:
- **UNIVERSAL LOGIN**: Qualquer provider (email, CPF, telefone, biometria, custom)
- **MFA MULTI-CAMADAS**: TOTP (RFC 6238), OTP via webhook, Passwordless
- **GESTÃO DE IDENTIDADES**: Link/unlink de múltiplas identidades por usuário
- **SEGURANÇA ADAPTATIVA**: Smart Lockout, Panic Revocation, Device Fingerprinting
- **POLÍTICAS SOBERANAS**: Regras por origin, provider, contexto
- **CRIPTOGRAFIA END-TO-END**: ECDH P-256 + HKDF + AES-256-GCM

## 1.2 Arquitetura de Tenancy

O sistema é 100% multi-tenant. Cada projeto (tenant) tem:
- Schema `auth` isolado no PostgreSQL
- Tabelas dedicadas: users, identities, sessions, policies
- Configurações soberanas independentes
- Isolamento completo de dados via RLS (Row Level Security)

Fluxo de Resolução de Tenant:
1. Requisição chega com `{slug}` na URL
2. RateLimitService.warmupProjectContext() resolve o tenant
3. L1 Cache (RAM V8) -> L2 Cache (Dragonfly) -> PostgreSQL
4. Project config carregado com auth_strategies, policies, jwt_secret

## 2.1 auth.users - Entidade Base

Propósito: Usuário abstrato, agnóstico de provider

```sql
CREATE TABLE auth.users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  last_sign_in_at TIMESTAMP WITH TIME ZONE,
  
  -- Metadados flexíveis (JSONB)
  raw_user_meta_data JSONB DEFAULT '{}',
  
  -- Estados
  banned BOOLEAN DEFAULT FALSE,
  email_confirmed_at TIMESTAMP WITH TIME ZONE,
  
  -- Tokens de confirmação
  confirmation_token TEXT,
  confirmation_sent_at TIMESTAMP WITH TIME ZONE
);

-- Índices
CREATE INDEX idx_users_email ON auth.users((raw_user_meta_data->>'email'));
CREATE INDEX idx_users_created_at ON auth.users(created_at DESC);
```

Campos importantes em raw_user_meta_data:
- `email`: Email principal do usuário
- `phone`: Telefone
- `name`: Nome do usuário
- `avatar_url`: URL do avatar
- `totp_pending_secret`: Segredo TOTP durante setup
- `mfa_enabled`: Boolean indicando MFA ativo

## 2.2 auth.identities - CORE CONCEPT

Propósito: Chaves de autenticação vinculadas ao usuário (1:N)

```sql
CREATE TABLE auth.identities (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  
  -- Provider e identificador
  provider TEXT NOT NULL,              -- 'email', 'cpf', 'phone', 'google', 'totp'
  identifier TEXT NOT NULL,              -- O valor (email, CPF, telefone)
  
  -- Credenciais
  password_hash TEXT,                  -- bcrypt hash (se aplicável)
  
  -- Metadados específicos da identidade
  identity_data JSONB DEFAULT '{}',
  
  -- Timestamps
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  last_sign_in_at TIMESTAMP WITH TIME ZONE,
  verified_at TIMESTAMP WITH TIME ZONE,  -- Email/identidade confirmada?
  
  -- Origem
  created_via_origin TEXT,             -- URL de onde foi criada
  
  -- Constraints
  UNIQUE(provider, identifier)
);

-- Índices críticos
CREATE INDEX idx_identities_user ON auth.identities(user_id);
CREATE INDEX idx_identities_provider_identifier ON auth.identities(provider, identifier);
CREATE INDEX idx_identities_provider ON auth.identities(provider);
```

### Exemplo Prático - Múltiplas Identidades:

```
User: usr_abc123 (João Silva)
├── Identity: provider='email', identifier='joao@email.com'
│             password_hash='$2b$10$...', verified_at='2026-01-15'
├── Identity: provider='cpf', identifier='123.456.789-00'
│             password_hash='$2b$10$...', verified_at='2026-01-15'
├── Identity: provider='phone', identifier='+5511999999999'
│             password_hash=NULL (passwordless), verified_at='2026-02-01'
├── Identity: provider='google', identifier='google_sub_123456'
│             password_hash=NULL (OAuth), verified_at='2026-01-20'
└── Identity: provider='totp', identifier='JBSWY3DPEHPK3PXP'
              password_hash=NULL (MFA secret), created_at='2026-03-01'
```

**Benefícios desta arquitetura:**
1. **Login Universal**: João pode logar com email, CPF OU telefone (mesma conta)
2. **Progressive Enhancement**: Começa com OAuth, adiciona senha depois
3. **MFA como Identity**: TOTP é apenas mais uma identity
4. **Unified Profile**: Todas as identidades levam ao mesmo usuário

## 2.3 auth.refresh_tokens - Sessões

Propósito: Tokens de refresh para sessões persistentes

```sql
CREATE TABLE auth.refresh_tokens (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  token_hash TEXT NOT NULL,              -- SHA256 do token
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  revoked BOOLEAN DEFAULT FALSE,
  
  -- Timestamps
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  expires_at TIMESTAMP WITH TIME ZONE NOT NULL,
  
  -- Token rotation
  parent_token UUID,                     -- Para detectar reuso
  
  -- Device fingerprinting
  ip_address TEXT,
  user_agent TEXT,
  fingerprint_hash TEXT                  -- Hash do device fingerprint
);

-- Índices
CREATE INDEX idx_refresh_tokens_user ON auth.refresh_tokens(user_id);
CREATE INDEX idx_refresh_tokens_hash ON auth.refresh_tokens(token_hash);
CREATE INDEX idx_refresh_tokens_expires ON auth.refresh_tokens(expires_at) 
  WHERE revoked = false;
```

Token Rotation:
```
1. Client envia: refresh_token = "rt_abc123"
2. Backend calcula: SHA256("rt_abc123") = "hash_xyz"
3. Verifica se existe e não está revoked
4. Gera novo: "rt_def456"
5. ATOMIC: UPDATE old SET revoked=true, INSERT new
6. Se old for reusado -> REVOKE ALL SESSIONS (possível ataque)
```

## 2.4 auth.otp_codes - Challenges

Propósito: Códigos OTP para passwordless, magic links, recovery

```sql
CREATE TABLE auth.otp_codes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  provider TEXT NOT NULL,                  -- Quem gerou
  identifier TEXT NOT NULL,                  -- Para quem
  code_hash TEXT NOT NULL,                 -- SHA256 do código
  expires_at TIMESTAMP WITH TIME ZONE NOT NULL,
  attempts INTEGER DEFAULT 0,              -- Tentativas de verificação
  metadata JSONB DEFAULT '{}',             -- { type: 'magiclink'|'recovery'|'signup' }
  ip_address TEXT,                         -- IP que solicitou
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  
  -- Constraint único com upsert
  UNIQUE(provider, identifier)
);

-- Índice para cleanup
CREATE INDEX idx_otp_codes_expires ON auth.otp_codes(expires_at);
```

Comportamento de UPSERT:
```sql
INSERT INTO auth.otp_codes (provider, identifier, code_hash, expires_at)
VALUES ('cpf', '123.456.789-00', 'sha256:abc...', NOW() + INTERVAL '15 min')
ON CONFLICT (provider, identifier) 
DO UPDATE SET 
  code_hash = EXCLUDED.code_hash,
  expires_at = EXCLUDED.expires_at,
  attempts = 0,
  ip_address = EXCLUDED.ip_address;
```

Isso garante:
- Apenas um código ativo por provider+identifier
- Novo código sobrescreve o antigo
- Attempts são resetados

## 2.5 auth.used_totp_codes - Anti-Replay

Propósito: Prevenir reuso de códigos TOTP (ataque replay)

```sql
CREATE TABLE auth.used_totp_codes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  code TEXT NOT NULL,                      -- Código que foi usado
  used_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Índice para cleanup (códigos antigos)
CREATE INDEX idx_used_totp_codes_at ON auth.used_totp_codes(used_at);
```

Janela de tolerância: 5 minutos
```sql
-- Verifica se código já foi usado
SELECT EXISTS(
  SELECT 1 FROM auth.used_totp_codes
  WHERE user_id = $1 AND code = $2
  AND used_at > NOW() - INTERVAL '5 minutes'
);
```

## 2.6 auth.policies - SOVEREIGN ORCHESTRATION

Propósito: Regras de autenticação por contexto (prioridade-based)

```sql
CREATE TABLE auth.policies (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  priority INTEGER DEFAULT 0,              -- MAIOR = mais prioritária
  
  -- Matching criteria (NULL = match all)
  provider TEXT,                           -- Qual provider afeta
  origin TEXT,                             -- Qual origin (pode usar wildcard)
  
  -- Regras de segurança
  require_password BOOLEAN DEFAULT true,
  require_otp BOOLEAN DEFAULT false,
  require_user_mfa_choice BOOLEAN DEFAULT false,
  auto_login BOOLEAN DEFAULT false,        -- Passwordless
  
  active BOOLEAN DEFAULT true,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Índice para resolução eficiente
CREATE INDEX idx_policies_priority ON auth.policies(priority DESC) WHERE active = true;
CREATE INDEX idx_policies_provider ON auth.policies(provider) WHERE active = true;
```

Algoritmo de Resolução (resolveSovereignPolicy):
```
1. Coleta todas as políticas ativas para o projeto
2. Filtra por provider (se policy.provider != NULL, deve bater)
3. Filtra por origin (suporta wildcard: '*.banco.com')
4. Ordena por priority DESC
5. Retorna a primeira que der match
```

Exemplo de Políticas:
```sql
-- Política 1: Externo MFA Obrigatório (prioridade 100)
INSERT INTO auth.policies (name, priority, provider, origin, require_password, require_otp, require_user_mfa_choice)
VALUES ('Externo MFA', 100, 'cpf', '*.externo.banco.com', true, true, true);

-- Política 2: Interno Passwordless (prioridade 50)
INSERT INTO auth.policies (name, priority, provider, origin, require_password, auto_login)
VALUES ('Interno Passwordless', 50, 'cpf', 'https://intranet.banco.com', false, true);

-- Política 3: Default (prioridade 0)
INSERT INTO auth.policies (name, priority, require_password)
VALUES ('Default', 0, true);
```

Resolução para login de CPF de *.externo.banco.com:
- Match Política 1 (priority 100) -> VENCE
- Requer: password + OTP (usuário pode escolher TOTP ou SMS)

## 2.7 auth.panic_revocations - EMERGÊNCIA

Propósito: Revogação imediata de acessos (Sovereign Panic)

```sql
CREATE TABLE auth.panic_revocations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  target_type TEXT CHECK ('origin', 'user', 'provider', 'global'),
  target_value TEXT,                       -- Qual origin/user/provider
  metadata JSONB DEFAULT '{}',             -- { reason: "...", triggered_by: "..." }
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_panic_revocations_target ON auth.panic_revocations(target_type, target_value);
CREATE INDEX idx_panic_revocations_created ON auth.panic_revocations(created_at DESC);
```

Modos de Revogação:

| target_type | Ação executada |
|-------------|----------------|
| `user` | Revoga todos os tokens do usuário específico |
| `origin` | Bloqueia todos logins daquele origin |
| `provider` | Bloqueia todos logins daquele provider |
| `global` | Revoga TUDO (app-wide lockdown) |

Implementação (Go + Dragonfly):
```go
// 1. Registra no PostgreSQL
pool.Exec(ctx, `INSERT INTO auth.panic_revocations ...`)

// 2. Set no Dragonfly (24h TTL)
dragonfly.Set(ctx, 
  fmt.Sprintf("panic:%s:%s", slug, target), 
  "true", 
  redis.KeepTTL
)

// 3. Se target='user', revoga tokens
pool.Exec(ctx, `UPDATE auth.refresh_tokens SET revoked = true WHERE user_id = $1`, userId)

// 4. Se target='global', revoga TUDO
pool.Exec(ctx, `UPDATE auth.refresh_tokens SET revoked = true`)
dragonfly.Set(ctx, fmt.Sprintf("panic:%s", slug), "true")
```

## 3.3 OTP Config

```typescript
interface OtpConfig {
  length?: number;                    // 4, 6, 8, 10 (padrão: 6)
  charset?: 'numeric' | 'alphanumeric' | 'alpha' | 'hex';
  expiration_minutes?: number;        // TTL do código (padrão: 15)
  regex_validation?: string;          // Regex para validar identifier
}
```

Geração de código (AuthService.ts):
```typescript
function generateOtpCode(config: OtpConfig): string {
  const length = config.length || 6;
  const charset = config.charset || 'numeric';
  
  const charsets = {
    numeric: '0123456789',
    alphanumeric: 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789',
    alpha: 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz',
    hex: '0123456789abcdef'
  };
  
  const chars = charsets[charset];
  let code = '';
  for (let i = 0; i < length; i++) {
    code += chars[Math.floor(Math.random() * chars.length)];
  }
  return code;
}
```

O webhook externo deve:
1. Validar a assinatura HMAC
2. Enviar o código via canal apropriado (SMS/WhatsApp/Email)
3. Retornar sucesso/falha

## 3.5 Modos de OTP Dispatch

| Modo | Descrição |
|------|-----------|
| `delegated` | Retorna 403 com lista de canais, frontend escolhe |
| `auto_current` | Envia automaticamente para o provider atual (ex: SMS para telefone) |
| `auto_primary` | Envia para o email principal da conta |

Implementação (GoTrueService.ts):
```typescript
if (strategyConfig.otp_dispatch_mode === 'delegated') {
  // Retorna erro com canais disponíveis
  throw { code: 'otp_delegated', channels: ['sms', 'whatsapp', 'email'] };
} else if (strategyConfig.otp_dispatch_mode === 'auto_current') {
  // Dispara webhook automaticamente
  await dispatchWebhook(strategyConfig.webhook_url, payload);
}
```

## 4.5 Fluxo Interno Detalhado (8 Passos)

### PASSO 1: FIREWALL (Dragonfly Check)

Local: `RateLimitService.checkAuthLockout()`

```typescript
async checkAuthLockout(slug, ip, identifier, config): Promise<{ locked, reason }> {
  const strategy = config.strategy || 'hybrid';
  const maxAttempts = config.max_attempts || 5;
  
  // 1. IP-Level Check (heurística: 3x = spraying attack)
  if (strategy === 'hybrid' || strategy === 'ip') {
    const ipKey = `lockout:ip:${slug}:${ip}`;
    const ipStrikes = parseInt(await dragonfly.get(ipKey) || '0');
    if (ipStrikes >= (maxAttempts * 3)) {
      return { 
        locked: true, 
        reason: `Too many failed attempts from your network. Locked for ${config.lockout_minutes} minutes.` 
      };
    }
  }
  
  // 2. Identifier-Level Check
  if (identifier && (strategy === 'hybrid' || strategy === 'identifier')) {
    const idKey = `lockout:id:${slug}:${identifier}`;
    const idStrikes = parseInt(await dragonfly.get(idKey) || '0');
    if (idStrikes >= maxAttempts) {
      return { 
        locked: true, 
        reason: `Too many failed attempts for this account. Locked for ${config.lockout_minutes} minutes.`
```

Algoritmo completo:
```typescript
async resolveSovereignPolicy(pool, projectConfig, provider, origin, context) {
  const authConfig = projectConfig?.auth_config || {};
  const strategyConfig = authConfig.auth_strategies?.[provider] || {};
  
  // Priority 1: Strategy Rules (metadata.rules)
  if (strategyConfig.rules) {
    for (const rule of strategyConfig.rules) {
      if (matchesOrigin(rule.origin, origin)) {
        return {
          name: `Strategy Rule: ${rule.origin}`,
          require_password: rule.require_password ?? true,
          require_otp: rule.require_otp ?? false,
          require_user_mfa_choice: rule.require_user_mfa_choice ?? false,
          auto_login: rule.auto_login ?? false,
          priority: 1000
        };
      }
    }
  }
  
  // Priority 2: Database Policies
  const result = await pool.query(`
    SELECT * FROM auth.policies 
    WHERE active = true 
      AND (provider IS NULL OR provider = $1)
      AND (origin IS NULL OR $2 LIKE origin)
    ORDER BY priority DESC
    LIMIT 1
  `, [provider, origin]);
  
  if (result.rows.length > 0) {
    return result.rows[0];
  }
  
  // Fallback: Default policy
  return {
    name: 'Default',
    require_password: true,
    require_otp: false,
    priority: 0
  };
}
```

Matching de Origin (suporta wildcard):
```typescript
function matchesOrigin(pattern: string, origin: string): boolean {
  if (pattern === origin) return true;
  if (pattern.endsWith('*')) {
    const prefix = pattern.slice(0, -1);
    return origin.startsWith(prefix);
  }
  if (pattern.includes('*.')) {
    const regex = new RegExp(pattern.replace(/\*\./, '.*\\.'));
    return regex.test(origin);
  }
  return false;
}
```

```typescript
async createSession(userId, pool, jwtSecret, ttl = '1h', refreshDays = 30, 
                    provider, deviceInfo) {
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    
    // 1. Gera Access Token (JWT)
    const now = Math.floor(Date.now() / 1000);
    const expiresIn = parseDuration(ttl);
    
    const payload = {
      sub: userId,
      role: 'authenticated',
      aud: 'authenticated',
      provider: provider,
      identifier: identifier,
      fpt: deviceInfo.fingerprint?.slice(0, 16) || 'unknown',
      iat: now,
      exp: now + expiresIn,
      app_metadata: { provider }
    };
    
    const accessToken = jwt.sign(payload, jwtSecret, { algorithm: 'HS256' });
    
    // 2. Gera Refresh Token
    const refreshToken = generateRandomToken(40); // 40 chars URL-safe
    const refreshHash = crypto.createHash('sha256').update(refreshToken).digest('hex');
    
    // 3. Armazena refresh token
    const fpBase = `${deviceInfo.ip}|${deviceInfo.userAgent}|${deviceInfo.fingerprint}`;
    const fpHash = crypto.createHash('sha256').update(fpBase).digest('hex');
    
    await client.query(`
      INSERT INTO auth.refresh_tokens (
        token_hash, user_id, expires_at, 
        ip_address, user_agent, fingerprint_hash
      ) VALUES ($1, $2, NOW() + INTERVAL '${refreshDays} days', $3, $4, $5)
    `, [refreshHash, userId, deviceInfo.ip, deviceInfo.userAgent, fpHash]);
    
    await client.query('COMMIT');
    
    return {
      access_token: accessToken,
      refresh_token: refreshToken,
      expires_in: expiresIn,
      user: await getUserWithIdentities(pool, userId)
    };
  } finally {
    client.release();
  }
}
```

```typescript
function verifyTOTP(secret: string, code: string): boolean {
  const counter = Math.floor(Date.now() / 1000 / 30); // 30s period
  
  // Verifica janela de ±1 período (clock drift)
  for (const offset of [-1, 0, 1]) {
    const expectedCode = generateHOTP(secret, counter + offset);
    if (timingSafeEqual(code, expectedCode)) {
      return true;
    }
  }
  return false;
}

function generateHOTP(secret: string, counter: number): string {
  // 1. Decode Base32
  const key = base32Decode(secret);
  
  // 2. Counter como 8 bytes big-endian
  const counterBytes = Buffer.alloc(8);
  counterBytes.writeBigUInt64BE(BigInt(counter));
  
  // 3. HMAC-SHA1
  const hmac = crypto.createHmac('sha1', key);
  hmac.update(counterBytes);
  const hash = hmac.digest();
  
  // 4. Dynamic Truncation (RFC 4226)
  const offset = hash[hash.length - 1] & 0x0f;
  const code = ((hash[offset] & 0x7f) << 24 |
                (hash[offset + 1] & 0xff) << 16 |
                (hash[offset + 2] & 0xff) << 8 |
                (hash[offset + 3] & 0xff)) % 1000000;
  
  // 5. Pad to 6 digits
  return code.toString().padStart(6, '0');
}
```

3. **Verifica anti-replay**:
```sql
SELECT EXISTS(
  SELECT 1 FROM auth.used_totp_codes
  WHERE user_id = $1 AND code = $2
  AND used_at > NOW() - INTERVAL '5 minutes'
);
```

### Fluxo de Rotação Segura

```typescript
async refreshSession(refreshToken, pool, jwtSecret, ttl, deviceInfo) {
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    
    // 1. Hash do token recebido
    const oldHash = crypto.createHash('sha256').update(refreshToken).digest('hex');
    
    // 2. Busca token no banco
    const tokenRes = await client.query(`
      SELECT * FROM auth.refresh_tokens 
      WHERE token_hash = $1 
        AND revoked = false 
        AND expires_at > NOW()
    `, [oldHash]);
    
    if (tokenRes.rows.length === 0) {
      throw new Error("Invalid refresh token");
    }
    
    const oldToken = tokenRes.rows[0];
    
    // 3. Verifica fingerprint (anti-hijacking)
    const fpBase = `${deviceInfo.ip}|${deviceInfo.userAgent}|${deviceInfo.fingerprint}`;
    const fpHash = crypto.createHash('sha256').update(fpBase).digest('hex');
    
    if (oldToken.fingerprint_hash && 
        !timingSafeEqual(oldToken.fingerprint_hash, fpHash)) {
      // Possível hijacking! Revoga tudo.
      await client.query(`
        UPDATE auth.refresh_tokens 
        SET revoked = true 
        WHERE user_id = $1
      `, [oldToken.user_id]);
      await client.query('COMMIT');
      throw new Error("Security violation: session hijacking detected");
    }
    
    // 4. Gera novo token
    const newToken = generateRandomToken(40);
    const newHash = crypto.createHash('sha256').update(newToken).digest('hex');
    
    // 5. Marca antigo como revoked, insere novo
    await client.query(`
      UPDATE auth.refresh_tokens 
      SET revoked = true 
      WHERE id = $1
    `, [oldToken.id]);
    
    await client.query(`
      INSERT INTO auth.refresh_tokens (
        token_hash, user_id, parent_token, expires_at,
        ip_address, user_agent, fingerprint_hash
      ) VALUES ($1, $2, $3, NOW() + INTERVAL '30 days', $4, $5, $6)
    `, [newHash, oldToken.user_id, oldToken.id, deviceInfo.ip, 
        deviceInfo.userAgent, fpHash]);
    
    // 6. Gera novo access token
    const accessToken = generateJWT(oldToken.user_id, jwtSecret, ttl);
    
    await client.query('COMMIT');
    
    return {
      access_token: accessToken,
      refresh_token: newToken,
      expires_in: parseDuration(ttl)
    };
  } catch (e) {
    await client.query('ROLLBACK');
    throw e;
  } finally {
    client.release();
  }
}
```

## 8.5 Logout Seguro (Blacklist)

### Endpoint
```
POST /api/data/{slug}/auth/logout
Authorization: Bearer {access_token}
```

### Fluxo

```typescript
async handleLogout(pool, accessToken, jwtSecret) {
  try {
    // Decodifica sem verificar (pode estar expirado)
    const decoded: any = jwt.verify(accessToken, jwtSecret, { 
      algorithms: ['HS256'] 
    });
    
    if (!decoded || !decoded.sub) return;
    
    // Calcula TTL restante
    const now = Math.floor(Date.now() / 1000);
    const ttl = decoded.exp - now;
    
    if (ttl > 0) {
      // Adiciona à blacklist no Dragonfly
      const tokenHash = crypto.createHash('sha256').update(accessToken).digest('hex');
      await dragonfly.set(
        `blacklist:jwt:${tokenHash}`, 
        'revoked', 
        'EX', 
        ttl
      );
    }
    
    return { success: true };
  } catch (e) {
    // Token inválido = já está "logout"
    return { success: true };
  }
}
```

### Verificação em Cada Request

Middleware de auth verifica blacklist:

```typescript
  }

}
```

## 9.1 Configuração

```json
{
  "auth_config": {
```

Estratégias:
- `ip`: Lock apenas por IP
- `identifier`: Lock apenas por identificador
- `hybrid`: Ambos (recomendado)
- `email`: Lock apenas para providers de email

## 9.2 Implementação (Dragonfly)

### Keys
```
lockout:ip:{slug}:{ip_address}       -> número de strikes
lockout:id:{slug}:{identifier}         -> número de strikes
```

### Check
```typescript
async checkAuthLockout(slug, ip, identifier, config) {
  const strategy = config.strategy || 'hybrid';
  const maxAttempts = config.max_attempts || 5;
  const lockoutMinutes = config.lockout_minutes || 15;
  
  // IP-Level
  if (strategy === 'hybrid' || strategy === 'ip') {
    const ipKey = `lockout:ip:${slug}:${ip}`;
    const ipStrikes = parseInt(await dragonfly.get(ipKey) || '0');
    
    // Heurística: 3x max = spraying attack
    if (ipStrikes >= (maxAttempts * 3)) {
      return {
        locked: true,
        reason: `Network locked due to suspicious activity. Try again in ${lockoutMinutes} minutes.`,
        retry_after: lockoutMinutes * 60
      };
    }
  }
  
  // Identifier-Level
  if (identifier && (strategy === 'hybrid' || strategy === 'identifier')) {
    const idKey = `lockout:id:${slug}:${identifier}`;
    const idStrikes = parseInt(await dragonfly.get(idKey) || '0');
    
    if (idStrikes >= maxAttempts) {
      return {
        locked: true,
        reason: `Account locked due to too many failed attempts. Try again in ${lockoutMinutes} minutes.`,
        retry_after: lockoutMinutes * 60
      };
    }
  }
  
  return { locked: false };
}
```

### Register Failure
```typescript
async registerAuthFailure(slug, ip, identifier, config) {
  const lockoutSeconds = (config.lockout_minutes || 15) * 60;
  
  const multi = dragonfly.multi();
  
  // Incrementa strikes
  multi.incr(`lockout:ip:${slug}:${ip}`);
  multi.expire(`lockout:ip:${slug}:${ip}`, lockoutSeconds);
  
  if (identifier) {
    multi.incr(`lockout:id:${slug}:${identifier}`);
    multi.expire(`lockout:id:${slug}:${identifier}`, lockoutSeconds);
  }
  
  await multi.exec();
}
```

```typescript
async panicRevocation(pool, dragonfly, slug, targetType, targetValue, reason) {
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    
    // 1. Registra revogação
    await client.query(`
      INSERT INTO auth.panic_revocations (target_type, target_value, metadata)
      VALUES ($1, $2, $3)
    `, [targetType, targetValue, JSON.stringify({ reason })]);
    
    // 2. Executa ações por tipo
    switch (targetType) {
      case 'user':
        // Encontra user_id
        const userRes = await client.query(`
          SELECT u.id FROM auth.users u
          JOIN auth.identities i ON u.id = i.user_id
          WHERE i.identifier = $1
        `, [targetValue]);
        
        if (userRes.rows.length > 0) {
          const userId = userRes.rows[0].id;
          
          // Revoga tokens
          await client.query(`
            UPDATE auth.refresh_tokens 
            SET revoked = true 
            WHERE user_id = $1
          `, [userId]);
          
          // Set no Dragonfly (24h)
          await dragonfly.set(
            `panic:user:${slug}:${userId}`,
            'true',
            'EX',
            86400
          );
        }
        break;
        
      case 'origin':
        await dragonfly.set(
          `panic:origin:${slug}:${targetValue}`,
          'true',
          'EX',
          86400
        );
        break;
        
      case 'provider':
        await dragonfly.set(
          `panic:provider:${slug}:${targetValue}`,
          'true',
          'EX',
          86400
        );
        break;
        
      case 'global':
        // Revoga TUDO
        await client.query(`
          UPDATE auth.refresh_tokens SET revoked = true
        `);
        await dragonfly.set(
          `panic:${slug}`,
          'true',
          'EX',
          86400
        );
        break;
    }
    
    await client.query('COMMIT');
    
    return { success: true };
  } catch (e) {
    await client.query('ROLLBACK');
    throw e;
  } finally {
    client.release();
  }
}
```

```typescript
async checkNeutralized(pool, dragonfly, slug, identifier, provider, userId) {
  // 1. Verifica PostgreSQL (persistente)
  const panicRes = await pool.query(`
    SELECT metadata->>'reason' as reason
    FROM auth.panic_revocations
    WHERE (target_type = 'user' AND target_value = $1)
       OR (target_type = 'global' AND target_value = 'ALL')
       OR (target_type = 'provider' AND target_value = $2)
    ORDER BY created_at DESC
    LIMIT 1
  `, [identifier, provider]);
  
  if (panicRes.rows.length > 0) {
    return {
      neutralized: true,
      reason: panicRes.rows[0].reason
    };
  }
  
  // 2. Verifica Dragonfly (cache rápido)
  if (userId) {
    const isUserNeutralized = await dragonfly.get(`panic:user:${slug}:${userId}`);
    if (isUserNeutralized === 'true') {
      return { neutralized: true, reason: "User neutralized" };
    }
  }
  
  const isGlobalPanic = await dragonfly.get(`panic:${slug}`);
  if (isGlobalPanic === 'true') {
    return { neutralized: true, reason: "Global panic mode active" };
  }
  
  return { neutralized: false };
}
```

## 10.1 Geração no Frontend

```typescript
function generateDeviceFingerprint(): string {
  const components = [
    navigator.userAgent,
    navigator.language,
    screen.colorDepth,
    `${screen.width}x${screen.height}`,
    new Date().getTimezoneOffset(),
    !!window.sessionStorage,
    !!window.localStorage,
    navigator.hardwareConcurrency,
    navigator.platform
  ];
  
  // Simple hash (não precisa ser criptográfico, apenas único)
  const str = components.join('|');
  let hash = 0;
  for (let i = 0; i < str.length; i++) {
    const char = str.charCodeAt(i);
    hash = ((hash << 5) - hash) + char;
    hash = hash & hash;
  }
  return Math.abs(hash).toString(16);
}
```

## 10.2 Geração no Backend

```typescript
function computeFingerprintHash(deviceInfo) {
  const fpBase = `${deviceInfo.ip}|${deviceInfo.userAgent}|${deviceInfo.fingerprint}`;
  return crypto.createHash('sha256').update(fpBase).digest('hex');
}
```

## 11.2 Fluxo Completo

### Passo 1: Handshake

```typescript
// Gera par de chaves efêmero
const keyPair = await crypto.subtle.generateKey(
  { name: 'ECDH', namedCurve: 'P-256' },
  false,  // extractable: false
  ['deriveBits']
);

const publicKeySpki = await crypto.subtle.exportKey('spki', keyPair.publicKey);
```

### Passo 2: Derivação de Chave (Frontend)

```typescript
// 1. Importa chave pública do servidor
const serverPublicKey = await crypto.subtle.importKey(
  'spki',
  base64ToArrayBuffer(serverPublicKeyBase64),
  { name: 'ECDH', namedCurve: 'P-256' },
  false,
  []
);

// 2. Gera par de chaves efêmero do cliente

  { name: 'ECDH', namedCurve: 'P-256' },
  false,
  ['deriveBits']
);

// 3. Deriva bits compartilhados

  { name: 'ECDH', public: serverPublicKey },
  clientKeyPair.privateKey,
  256
);

// 4. HKDF para chave AES
const aesKey = await crypto.subtle.deriveKey(
  {
    name: 'HKDF',
    hash: 'SHA-256',
    salt: new Uint8Array(0),
    info: new TextEncoder().encode(`cascata-v2-${serverFingerprint}`)
  },
  await crypto.subtle.importKey('raw', sharedBits, 'HKDF', false, ['deriveKey']),
  { name: 'AES-GCM', length: 256 },

);
```

### Passo 5: Decifragem (Backend)

```typescript
async function decryptLoginPayload(sessionId, clientPublicKeyBase64, 
                                   ivBase64, authTagBase64, 
                                   ciphertextBase64, timestamp) {
  // 1. Recupera chave privada
  const privateKey = await cache.get(`handshake:${sessionId}:privateKey`);
  if (!privateKey) {
    throw new Error("Handshake expired");
  }
  
  // 2. Importa chave pública do cliente
  const clientPublicKey = await crypto.subtle.importKey(
    'spki',
    base64ToArrayBuffer(clientPublicKeyBase64),
    { name: 'ECDH', namedCurve: 'P-256' },
    false,
    []
  );
  
  // 3. Deriva mesmos bits compartilhados
  const sharedBits = await crypto.subtle.deriveBits(
    { name: 'ECDH', public: clientPublicKey },
    privateKey,
    256
  );
  
  // 4. Deriva mesma chave AES via HKDF
  const aesKey = await crypto.subtle.deriveKey(
    {
      name: 'HKDF',
      hash: 'SHA-256',
      salt: new Uint8Array(0),
      info: new TextEncoder().encode(`cascata-v2-${serverFingerprint}`)
    },
    await crypto.subtle.importKey('raw', sharedBits, 'HKDF', false, ['deriveKey']),
    { name: 'AES-GCM', length: 256 },
    false,
    ['decrypt']
  );
  
  // 5. Recompõe e decifra
  const iv = base64ToArrayBuffer(ivBase64);
  const authTag = base64ToArrayBuffer(authTagBase64);
  const ciphertext = base64ToArrayBuffer(ciphertextBase64);
  
  // ciphertext || authTag
  const encrypted = new Uint8Array(ciphertext.length + authTag.length);
  encrypted.set(ciphertext, 0);
  encrypted.set(authTag, ciphertext.length);
  
  const decrypted = await crypto.subtle.decrypt(
    { name: 'AES-GCM', iv },
    aesKey,
    encrypted
  );
  
  const payload = JSON.parse(new TextDecoder().decode(decrypted));
  
  // 6. Valida anti-replay (±90s)
  const now = Date.now();
  if (Math.abs(now - payload._ts) > 90000) {
    throw new Error("Request expired (anti-replay)");
  }
  
  return payload;
}
```

### Passo 6: Resposta Cifrada

O backend cifra a resposta (token, user) com a mesma chave AES:

```typescript
const responsePlaintext = JSON.stringify({
  token: accessToken,
  user: userData
});

const responseIv = crypto.getRandomValues(new Uint8Array(12));
const responseEncrypted = await crypto.subtle.encrypt(
  { name: 'AES-GCM', iv: responseIv },
  aesKey,
  new TextEncoder().encode(responsePlaintext)
);

return {
  iv: arrayBufferToBase64(responseIv),
  authTag: arrayBufferToBase64(responseEncrypted.slice(-16)),
  ciphertext: arrayBufferToBase64(responseEncrypted.slice(0, -16))
};
```

O frontend decifra e obtém o token.

## 11.3 Proteções

| Proteção | Implementação |
|----------|---------------|
| Anti-replay | Timestamp ±90s |
| Anti-tampering | Auth tag AES-GCM |
| Forward secrecy | Chaves efêmeras, descartadas após uso |
| No storage | Chaves nunca persistem em disco |
| Perfect secrecy | Cada handshake tem chaves únicas |

```typescript
function resolveLanguage(template: MessagingTemplate, requestedLang: string): string {
  // 1. Idioma exato
  if (template.variants[requestedLang]) {
    return requestedLang;
  }
  
  // 2. Base do idioma (pt-BR -> pt)
  const baseLang = requestedLang.split('-')[0];
  const matchingLang = Object.keys(template.variants)
    .find(lang => lang.startsWith(baseLang));
  if (matchingLang) {
    return matchingLang;
  }
  
  // 3. Idioma padrão do template
  if (template.variants[template.default_language]) {
    return template.default_language;
  }
  
  // 4. Primeiro disponível
  return Object.keys(template.variants)[0];
}
```

## 3. O Fluxo de Vida de uma Requisição (Como o RLS funciona)

Aqui está o segredo de como o `auth.uid()` funciona sem que o banco saiba de sessões. Ocorre uma **Troca de Contexto** a cada milissegundo.

### Passo 1: O Passaporte (JWT)
Quando o usuário loga (seja por Google, Senha ou Magic Link), o Backend (Node.js) valida a credencial na tabela `auth.identities`. Se válido, ele assina um **JWT (JSON Web Token)** usando a `JWT_SECRET` do projeto.

O JWT contém:
```json
{
  "sub": "uuid-do-auth-users",  <-- O Âncora
  "role": "authenticated",      <-- O Papel
  "email": "user@email.com",
  "exp": 1715000000
}
```

### Passo 2: A Chegada no Data Plane
O usuário faz um request: `GET /rest/v1/todos`.
Ele envia o header: `Authorization: Bearer <JWT>`.

O Backend (Express/Middleware):
1.  Verifica a assinatura do JWT (garante que não foi falsificado).
2.  Extrai o `sub` (UUID) e `role`.
3.  Pega uma conexão do Pool do banco de dados (que é genérica, usada por todos).

### Passo 3: A Injeção de Contexto (A Mágica)
Antes de rodar a query do usuário, o Backend executa comandos de sessão local no Postgres **dentro da mesma transação**:

```sql
-- O Backend roda isso invisivelmente:
BEGIN;
-- Define a role do banco para limitar poderes gerais
SET LOCAL ROLE cascata_api_role; 

-- Injeta variáveis de configuração de sessão (GUCs)
SELECT set_config('request.jwt.claim.sub', 'uuid-do-usuario', true);
SELECT set_config('request.jwt.claim.role', 'authenticated', true);
SELECT set_config('request.jwt.claim.email', 'email-do-usuario', true);

-- AGORA roda a query do usuário
SELECT * FROM public.todos;

-- Limpa tudo antes de devolver a conexão para o Pool
COMMIT;
```

### Passo 4: A Função auth.uid()
Agora faz sentido as funções que criei na migration `013`.
Quando o Postgres está rodando o `SELECT` acima e encontra uma política RLS:

```sql
CREATE POLICY "Meus Dados" ON public.todos
USING ( user_id = auth.uid() );
```

A função `auth.uid()` faz exatamente isto:
```sql
-- Ele lê a variável que injetamos no Passo 3
SELECT current_setting('request.jwt.claim.sub', true)::uuid;
```

### Resultado
O PostgreSQL "pensa" que aquela conexão pertence àquele usuário específico apenas durante aqueles milissegundos da execução. Isso garante isolamento total de dados entre usuários, mesmo usando um Pool de conexões compartilhado.

## 4. Onde a "Revolução" Acontece

O seu conceito de "Concatenação" é poderoso porque desacopla a **Autenticação** (provar quem sou) da **Autorização** (o que meu UUID pode fazer).

1.  **Multi-Factor Nativo:** Como as identidades são uma lista (`1:N`), você pode exigir no futuro que um usuário tenha *duas* identidades validadas (ex: Senha + SMS) antes de emitir o JWT.
2.  **Identidades Corporativas:** Você pode vincular um Login Google Workspace E um Login Microsoft AD ao mesmo UUID. O usuário vê os mesmos dados independente de por onde entrou.
3.  **Migração Invisível:** Se você quiser migrar de Auth0 para Cascata, basta criar as entradas em `auth.identities` mantendo os UUIDs em `auth.users`. O usuário nem percebe.

## 5. Resumo Clínico

*   **Front-end:** Envia credenciais -> Recebe JWT.
*   **Back-end:** Valida Credencial -> Emite JWT -> Recebe Request -> Injeta Variáveis no SQL -> Executa Query.
*   **Database:** Não sabe de nada, apenas lê `current_setting('request.jwt.claim.sub')` via `auth.uid()` e filtra as linhas.

Esta arquitetura é "Stateless" (sem estado) no servidor, infinitamente escalável e extremamente segura, pois a regra de segurança vive junto com o dado (no banco), não no código Javascript.
