# Plano de Correção: Rate Limits Backend e Frontend

Este plano corrige os problemas graves no sistema de rate limits onde os dados enviados pelo frontend não são salvos corretamente pelo backend.

## Resumo dos Problemas

**Enviado pelo Frontend:**
- `window_seconds_anon`: 5000, `window_seconds_auth`: 6000
- `burst_limit_anon`: 0, `burst_limit_auth`: 0
- `message_anon`: "Crie sua conta", `message_auth`: "Aumente seu plano"
- `metadata.crud_limits`: objeto com anon/auth
- `metadata.group_limits`: {}
- `metadata.time_windows`: array de objetos
- `metadata.operation_weights`: objeto
- `metadata.is_cumulative`: objeto por operação

**Salvo pelo Backend:**
- `window_seconds`: 1 (hardcoded default)
- `burst_limit_anon`: 5, `burst_limit_auth`: 10 (hardcoded defaults)
- `message_anon`: null, `message_auth`: null
- `crud_limits`: null
- `time_windows`: null
- `is_cumulative`: false (boolean único)
- `operation_weights`: valores padrão

## Parte 1: Backend - Database Migration

### 1.1 Adicionar colunas faltantes à tabela `rate_limits`

Criar arquivo `backend/migrations/037_fix_rate_limits_columns.sql`:

```sql
-- Adiciona colunas para janelas de tempo separadas para anon e auth
ALTER TABLE system.rate_limits
ADD COLUMN IF NOT EXISTS window_seconds_anon INTEGER DEFAULT 1,
ADD COLUMN IF NOT EXISTS window_seconds_auth INTEGER DEFAULT 1;

-- Comentários
COMMENT ON COLUMN system.rate_limits.window_seconds_anon IS 'Janela de tempo em segundos para usuários anônimos';
COMMENT ON COLUMN system.rate_limits.window_seconds_auth IS 'Janela de tempo em segundos para usuários autenticados';
```

## Parte 3: Frontend - Correção do Modal

### 3.1 Verificar formato de envio em `RLSManager.tsx`

O frontend atualmente envia dados em formato incorreto. Precisa alinhar com o backend:

**Problema:** Frontend envia `window_seconds_anon` e `window_seconds_auth` separados, mas backend espera `window_seconds` (singular) ou as novas colunas.

**Solução:** Após a migration, o backend aceitará ambos os formatos. O frontend deve continuar enviando `window_seconds_anon` e `window_seconds_auth`.

### 3.2 Corrigir lógica de `is_cumulative`

**Problema:** Frontend envia `is_cumulative` como objeto por operação, mas tabela tem boolean único.

**Solução:** Backend converterá o objeto para boolean (true se qualquer operação for true). Frontend pode continuar enviando no formato atual, ou simplificar para boolean único.

**Opção A (simplificar frontend):**
```typescript
// Mudar de objeto para boolean único
is_cumulative: true  // ou false
```

**Opção B (manter formato atual):**
Backend converte objeto para boolean automaticamente (já implementado no plano acima).
